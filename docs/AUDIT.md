# Аудит model-gate — 2026-10-23

## Область проверки

Проверены все модули proxy/допуска/lifecycle/статистики/панели, launcher,
тесты, пример конфигурации, README и настройки GitHub. Расчётная нагрузка:
один пользователь, несколько клиентов и backend-ов, длинные streaming-запросы.
Это не аудит многопользовательского публичного inference-сервиса.

Исходное состояние: 28 проходящих тестов, CI отсутствовал. Добавлены unit- и
изолированные HTTP integration-тесты: **66 тестов проходят локально**.
Модели и внешний inference для проверок не запускались.

## Исправленные проблемы

| Приоритет | Где | Случай и исправление |
|---|---|---|
| Высокий | `proxy.py: Lifecycle._unload` | Переход с process-backend-а на resident backend забывал модель, но оставлял старый процесс и веса в памяти. Теперь старый процесс останавливается до загрузки следующей модели. |
| Высокий | `proxy.py: Lifecycle._is_loaded` | Сетевая ошибка проверки loaded превращалась в `False`, unload пропускался. Неизвестное состояние теперь останавливает переключение, а не считается освобождённой памятью. |
| Высокий | `proxy.py: _admin_allowed`, `_read_body` | Web-страница могла послать simple POST с JSON-текстом на loopback admin API; DNS rebinding обходил проверку только IP клиента. Добавлены проверки Origin/Host/Sec-Fetch-Site и типа тела. Это не защита от доверенного локального процесса. |
| Средний | `proxy.py: _forward`, `_relay` | Backend HTTP 4xx/5xx превращались в 502, обрыв стрима мог добавить второй HTTP-ответ. Сохраняются статус/тело ошибки, после отправленных заголовков соединение только закрывается. Укороченный Content-Length учитывается как ошибка. |
| Средний | `proxy.py: _forward`, `_copy_headers` | Автоматический redirect мог отправить Authorization на другой URL. Redirect больше не выполняется; hop-by-hop заголовки и названные в Connection поля не пересылаются. |
| Средний | `proxy.py: cancel` | `HTTPResponse.close()` из admin-потока мог ждать блокирующий read или гоняться с read1. Сначала прерывается сокет, объект закрывает только владеющий им поток; отмена не считается ошибкой backend-а. |
| Средний | `panel.py: Actions.clear_kv`, `proxy.py: _clear_kv` | K искал каталог через ps после остановки процесса: путь пропадал, очистка становилась no-op. Операция перенесена в gate: путь из конфигурации работающего процесса, остановка и удаление под блокировкой допуска. При активном inference — 409. Симлинки файлов не удаляются. |
| Средний | `proxy.py: ProcessManager` | Readiness polling держал lock и блокировал status при запуске модели. Ожидание вынесено из lock. При startup timeout процесс останавливается; shutdown ожидает завершения, а не оставляет старый backend рядом с новым gate. |
| Средний | `gate.py`, `router.py`, `proxy.py: do_POST` | Точные model ID ошибочно считались префиксами; command-only ID не маршрутизировались; новые модели теряли backend max_concurrency. Исправлены точное сопоставление, источники ID и политика допуска. Для ожидания очереди добавлен конечный queue_timeout. |
| Средний | `mgrun`, `panel.py: Actions` | Устаревший PID мог остановить чужой процесс; параллельные launcher-ы перезаписывали PID. Добавлены проверка процесса, сериализация launcher-а и атомарная запись PID. R сохраняет выбранный config, локальные process-команды запрещены для remote URL. |
| Средний | `panel.py: Tty` | Один read считался одной клавишей: терялись склеенные стрелки/focus и фрагменты escape-последовательности. Добавлен входной буфер. Текст моделей/ошибок больше не может вставить управляющие коды терминала, в том числе OSC 52. |
| Средний | `stats.py` | Некорректный usage ломал finish и оставлял in-flight запись; JSON-парсер ошибался на скобках в строках; decode обновлял timestamp старого prefill. Добавлены безопасные числа, JSONDecoder и отдельное время prefill. |
| Низкий | `panel.py` | Компактный режим не показывал потерю gate; третий backend обрезался; жирность цвета протекала на другие роли. Исправлены error-header, расчёт ширины и сброс SGR. TTFB и end-to-end скорость больше не подписаны как token TTFT / decode. |
| Низкий | `panel.py: Poller` | Debug-файлы GPU писались в предсказуемые /tmp-пути; stop затенял внутренний метод Thread. Удалён постоянно включённый debug dump, используется временный файл, исправлено имя Event и cleanup helper-процессов при выходе из TUI. |

Тесты воспроизводят исходные ошибки до исправлений. HTTP-проверки отдельно
покрывают 429, redirect, SSE, оборванное тело, отмену молчащего backend-а,
некорректный JSON и браузерные запросы. Нет зависимости от установленных моделей.

## README и GitHub

- Удалены противоречивые утверждения: объединённый список в корневом `/v1/models`,
  автоматическая выгрузка чужих моделей, «контекст на SSD», универсальные цифры
  памяти и context limit, `o` как admin API, `p` как остановка опроса.
- Удалена рекомендация широкого wildcard NOPASSWD-правила. GPU-сбор опционален,
  `--no-gpu` не требует интерактивного sudo. Особенности macOS указаны явно.
- Документированы реальные ограничения отмены/очереди, API, источники метрик,
  хранение приватного KV, сетевые таймауты и одноэкземплярное состояние launcher-а.
- Пример слушает loopback и для proxy, и для дочерних серверов.
- Добавлены `SECURITY.md`, CI на Linux/macOS с Python 3.11/3.13 и private
  vulnerability reporting в GitHub. MIT, публичность и topics проверены.
- Ветки/история не переписывались. Старые PR refs оставлены по ранее принятому
  решению владельца; force-push их не удаляет. Новые изменения идут прямо в main.

## Что ещё ограничено и какие фичи действительно нужны

1. **Атомарный emergency stop / halt** — главный следующий шаг.
   Сейчас X отменяет snapshot запросов и последовательно останавливает процессы.
   Между этими действиями может прийти новый запрос или выйти старый из очереди,
   а resident backend без managed process остаётся загруженным. Нужен один
   server-side halt: запрет нового допуска → отмена активных/ожидающих → выгрузка
   всех backend-ов; явный resume. Это отвечает реальному сценарию «снять нагрузку».
2. **Отменяемая очередь с возрастом и причиной ожидания.** Сейчас ожидающий запрос
   имеет только общий счётчик, не попадает в LIVE до допуска, и разрыв клиентского
   соединения не удаляет его немедленно. Он может позже занять GPU. Есть timeout,
   но нужны ID, отмена ожидания и проверка живости клиента; заодно можно убрать
   голодание другой модели при постоянном потоке текущей. Не нужен отдельный broker.
3. **Preflight/doctor конфигурации без запуска весов.** Проверить пути бинарника,
   GGUF/encoder/MTP, свободное место KV, лимиты, конфликты model ID, поддержку
   status/load/unload и доступность портов. Это дешевле, чем ждать неудачной загрузки.
4. **Профилированное состояние экземпляра.** PID и выбранная модель всё ещё общие
   для машины. Если действительно понадобится несколько gate/config, перенести их
   в приватный каталог состояния с ключом от config и связывать PID с конкретным
   config/URL. Сейчас поддерживается один экземпляр; не добавлен менеджер профилей.

Дополнительные границы: `/healthz` проверяет сам gate, не готовность модели;
проверка status resident backend-а может ждать его медленный load endpoint;
известные модели discovery пока не удаляются автоматически. Веса, KV и временные
буферы разных моделей требуют отдельных измерений, не линейной экстраполяции из
одного запуска. Для публичного сетевого сервиса потребовались бы аутентификация,
ограничение соединений/очереди и отдельная модель угроз — в этот проект такой
режим не добавлялся.
